# التقارير الأسبوعية – الابتدائية السابعة والعشرون بعد المائة

صفحة ويب ثابتة (Static Web App) تتيح لوكيلات المدرسة تعبئة ثلاثة تقارير أسبوعية وتنزيل كل تقرير بصيغة PDF رسمية بمقاس A4:

- تقرير الشؤون المدرسية
- تقرير الشؤون التعليمية
- تقرير الشؤون الطلابية

لا توجد قاعدة بيانات ولا خادم ولا تسجيل دخول. كل شيء يعمل داخل المتصفح، ولا تُرسل أي إجابة إلى أي جهة.

---

## 1. قبل التشغيل: الشعاران

ضعي الملفين التاليين بنفس الاسم تمامًا:

| الملف | المحتوى |
| --- | --- |
| `public/assets/school-logo.png` | شعار المدرسة (يظهر يمين الترويسة) |
| `public/assets/moe-logo.png` | شعار وزارة التعليم الرسمي (يظهر يسار الترويسة) |

- يفضّل PNG بخلفية شفافة وعرض 400 بكسل أو أكثر.
- الشعار يُعرض داخل إطار ثابت مع الحفاظ على تناسب أبعاده، فلا يتمدد ولا يتشوه.
- إذا لم يوجد الملف يظهر مكانه إطار فارغ مكتوب فيه اسم الشعار.

## 2. التشغيل والمعاينة محليًا

يتطلب [Node.js](https://nodejs.org) الإصدار 18 أو أحدث.

```bash
npm install        # مرة واحدة فقط
npm run dev        # تشغيل نسخة التطوير على http://localhost:5173
```

لمعاينة النسخة النهائية كما ستُنشر:

```bash
npm run build      # ينشئ مجلد dist
npm run preview    # يعرضه على http://localhost:4173
```

## 3. تعديل الأسئلة والبيانات

كل البنود محفوظة في ملفات منظمة، ولا تحتاجين لتعديل أي كود آخر:

| الملف | ما يحتويه |
| --- | --- |
| `src/config/school.js` | أسطر الترويسة، اسم المدرسة، اسم مديرة المدرسة، الفصول الدراسية، أيام الأسبوع |
| `src/config/baseFields.js` | البيانات الأساسية أعلى كل استمارة (اسم الوكيلة، الأسبوع، التواريخ…) |
| `src/config/forms/schoolAffairs.js` | بنود الشؤون المدرسية |
| `src/config/forms/educationalAffairs.js` | بنود الشؤون التعليمية |
| `src/config/forms/studentAffairs.js` | بنود الشؤون الطلابية |
| `src/config/forms/index.js` | شرح أنواع البنود المتاحة |

أمثلة:

```js
// بند عددي
{ id: 'incoming', type: 'number', label: 'عدد المعاملات الواردة' },

// نعم / لا / لا ينطبق، مع مربع ملاحظات يظهر عند اختيار «لا»
{ id: 'spendingClosed', type: 'yesno', label: 'هل تم اعتماد الصرف في النظام؟',
  note: { when: 'no', label: 'سبب عدم الإغلاق' } },

// جدول بصفوف قابلة للإضافة والحذف
{ id: 'meetings', type: 'table', label: 'تفاصيل الاجتماعات', addLabel: 'إضافة اجتماع',
  columns: [
    { id: 'date', label: 'التاريخ', type: 'date', width: 20 },
    { id: 'topic', label: 'الموضوع', type: 'text', width: 80 },
  ] },
```

- تغيير `label` يغيّر المسمى في الاستمارة وفي ملف PDF معًا.
- لا تغيّري `id` لبند مستخدم؛ فهو مفتاح البيانات والمسودات.
- `sensitive: true` يمنع حفظ البند في المسودة المحلية (للأسماء والحالات)، ويظهر بجواره في الاستمارة تنبيه بأن النص يظهر في ملف PDF ولا يُستعاد من المسودة.
- عند تغيّر معنى بند أو نطاقه يُعطى `id` جديدًا، ويُترك المعرّف القديم دون استخدام (انظري التعليق أعلى كل ملف استمارة) حتى لا تظهر قيمه القديمة تحت المسمى الجديد.

## 4. طريقة إنتاج ملف PDF

- يُبنى التقرير كصفحات HTML بمقاس A4 مستقلة، فيعرضها محرك المتصفح نفسه بخط Tajawal المضمّن محليًا. لذلك تبقى الحروف العربية متصلة، والاتجاه من اليمين لليسار سليمًا، والأرقام والتواريخ في ترتيبها الصحيح.
- تُوزَّع البنود على الصفحات بحيث لا ينقسم صف جدول بين صفحتين، ولا يبقى عنوان قسم وحيدًا في أسفل الصفحة. وتتكرر الترويسة ورأس الجدول في كل صفحة مع ترقيم «صفحة 1 من 3».
- النص الطويل جدًا لا يُقص، بل يكمل في الصفحة التالية مع كلمة «(تابع)».
- زر **تنزيل PDF** يحوّل كل صفحة إلى صورة عالية الدقة ثم يجمعها في ملف PDF (باستخدام html2canvas-pro وjsPDF) ويُنزّله باسم مثل:
  `تقرير-الشؤون-التعليمية-الأسبوع-5.pdf`
- في نافذة **المعاينة** يوجد زر **طباعة** يفتح نافذة طباعة المتصفح، ويمكن منها اختيار «حفظ بصيغة PDF» للحصول على نص قابل للتحديد والنسخ.
- أي بند بلا إجابة يظهر بعلامة «—»، والصفر يظهر «0»، فلا يختلط الصفر بالحقل الفارغ.

## 5. الخصوصية والبيانات

- لا تُرسل أي بيانات إلى خادم، ولا تُخزن في GitHub.
- البيانات تبقى في ذاكرة الصفحة فقط، وتضيع عند إغلاقها ما لم يُنزَّل التقرير.
- زر «حفظ مسودة على هذا الجهاز» اختياري، ويظهر قبله تنبيه بأن التخزين المحلي (localStorage) غير آمن للبيانات الحساسة. البنود الحساسة (أسماء المعلمات والحالات) لا تُحفظ في المسودة.
- تنزيل PDF لا يعني إرسال التقرير للمديرة؛ يجب إرسال الملف يدويًا عبر واتساب أو البريد الإلكتروني.
- نسخة النشر تحتوي سياسة أمان (Content-Security-Policy) في `vite.config.js` تمنع المتصفح من الاتصال بأي جهة خارجية أو إرسال نماذج؛ كل الملفات (السكربتات والخطوط والشعاران) تُحمَّل من الموقع نفسه.

## 6. النشر على GitHub Pages

المستودع: `AlalawiRabab/weekly-reports-127` (عام، لأن GitHub Pages المجاني يتطلب مستودعًا عامًا؛ لا يحتوي أي بيانات تقارير).

```bash
git add .
git commit -m "التقارير الأسبوعية – الابتدائية 127"
git branch -M main
gh repo create AlalawiRabab/weekly-reports-127 --public --source . --remote origin --description "التقارير الأسبوعية – الابتدائية السابعة والعشرون بعد المائة"
gh api -X POST repos/AlalawiRabab/weekly-reports-127/pages -f build_type=workflow
git push -u origin main
```

- يعمل ملف `.github/workflows/deploy.yml` تلقائيًا بعد كل رفع إلى `main`: يبني المشروع، ويتأكد من وجود الشعارين، ثم ينشر مجلد `dist` فقط.
- الرابط: `https://alalawirabab.github.io/weekly-reports-127/` (HTTPS)، جاهز للمشاركة عبر واتساب.
- يمكن متابعة النشر من تبويب **Actions** في المستودع.

المسارات نسبية (`base: './'` في `vite.config.js`)، فيعمل الموقع داخل أي مستودع فرعي دون تعديل. التنقل بين الصفحات يتم عبر `#/` فلا تظهر أخطاء 404 عند تحديث الصفحة.

لا تُرفع إلى المستودع: `node_modules` و`dist` وأي ملف PDF، ولا النسختان الأصليتان للشعارين في جذر المشروع (انظري `.gitignore`).

## 7. ملاحظات للاستخدام على الجوال

- يُفضل فتح الرابط في Safari أو Chrome. بعض المتصفحات المدمجة داخل التطبيقات (مثل متصفح واتساب الداخلي) قد تمنع تنزيل الملفات؛ عندها اختاري «فتح في المتصفح».
- بعد التنزيل يظهر زر «مشاركة الملف» على الأجهزة التي تدعم ذلك، لإرسال الملف مباشرة عبر واتساب أو البريد.

## 8. هيكل المشروع

```
index.html
vite.config.js
public/assets/            الشعاران
src/
  main.js                 نقطة البداية والتنقل بين الصفحات
  config/                 كل النصوص والبنود القابلة للتعديل
  ui/                     الواجهة: الرئيسية، الاستمارة، الحقول، النوافذ
  report/                 بناء التقرير، توزيعه على صفحات A4، المعاينة، PDF
  utils/                  التواريخ والأرقام، المسودة المحلية
  styles/                 base.css و app.css و report.css
```
